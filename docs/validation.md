# Validation

Run the Go suite, race detector and static analysis:

```sh
go test -race ./...
go vet ./...
```

Tests use real SQLite, local HTTP/WebSocket servers and executable subprocess fixtures. They cover authenticated thread routing, source allowlists, identity and agent handoffs, new-message-only native continuations, durable retry prompts and idle TTL policies, uncertain delivery, Unicode/multipart output, cursor recovery, native assistant streams, 👀 reactions and graceful cancellation. TTL coverage includes the 30-minute default for human and automation dispatches with either agent, duration validation, optional/canonical CLI arguments, retries across configuration changes, preservation of older dispatches without a TTL, and routing replies to stopped Codex and Claude tasks through the existing message receipt path. Both `claimed` and `uncertain` receipts stop automatic replay; confirmed `pending` deliveries retry with their original external ID.

Default repository coverage includes mentions in unlisted public/private channels, parent alert context, duplicate events, pending replies, restart/resume, channel overrides and frozen repositories on retries. It also verifies that the fallback excludes other workspaces, direct messages, unrelated chatter and bot messages, and that automatic triggers still require explicitly configured channels.

Mention policy coverage verifies that `requireMention` rejects untagged human roots and replies before dispatch, including pending and restarted threads, automatic subscriptions and human triggers. Source-only bot triggers accept exact allowed sources in roots and replies while excluding other bots, other workspaces/channels, edits, hidden events and duplicates.

Image coverage includes image-only thread messages, missing file metadata, authenticated private downloads, rejected remote hosts and redirects, non-image and oversized responses, current-message recovery from thread history, per-task deduplication, separate participant tasks, frozen bytes across pending delivery and restart, and removal of delivered bytes from pending payloads. Paddock separately tests manifest validation, content-based message idempotency, private cached images, and sandbox upload without a live model.

## State migration

`internal/arnold/testdata/node-state.sqlite` was generated by the original Node implementation using synthetic data only. The migration test copies it to a temporary directory and proves that the Go implementation preserves:

- Thread/identity bindings and the existing task reference.
- A frozen pending follow-up, including its original external ID and prompt.
- Output cursors and previously delivered output receipts.
- Stream timestamps and counters.
- Pending reaction metadata.

The same single-instance SQLite lease prevents the Go binary and Node service from owning a state database simultaneously. Database and sidecar files use owner-only access.

## Installed Paddock contract

```sh
ARNOLD_PADDOCK_TEST_BIN="$(command -v paddock)" go test -race ./...
```

This optional test runs the installed Paddock output CLI against a disposable registry and deterministic native RPC fixture. It exercises Paddock's actual opaque cursors, bounded pages, multipart answers and native turn completion, followed by delivery failure and service-state restart. It launches no model, uses no credentials and reads no existing tasks. Without the variable, the installed-CLI test is skipped.

The installed-CLI suite also seeds a disposable repository, identity and prior TTL dispatch for both Codex and Claude. It verifies that Arnold's `run --idle-ttl` retries return the same task for equivalent durations and surface Paddock's conflict for a changed or omitted policy. It starts no sandbox or poller. Actual idle shutdown and native resume remain Paddock's responsibility and are tested in that repository.

## Binary and supervision

```sh
make build
bin/arnold version
mkdir -p state
bin/arnold launchd --directory "$PWD" > state/dev.arnold.slack.plist
plutil -lint state/dev.arnold.slack.plist
```

The binary is built with `CGO_ENABLED=0` and `-trimpath`. A live Node-to-Go handoff retained the existing routing, receipts, cursors, streams and reaction state, and the executable reconnected to Slack through launchd. SQLite is pure Go. The LaunchAgent invokes the executable directly and loads tokens from the local environment file.

## Live acceptance

Before enabling TTL dispatches, verify the runtime requirements in [Paddock's integration contract](https://github.com/nickdirienzo/paddock/blob/main/docs/integrations.md#per-task-idle-ttl-contract):

1. Rebuild the runtime image from the updated Paddock checkout, retaining any project-specific image layers, and pin its immutable image ID with `paddock runtime configure --image sha256:IMAGE_ID`. Check launcher-specific runtime images too.
2. Verify the image contains Claude Code 2.1.325, `paddock-idle`, `paddock-claude-idle` and the system Python `websockets` module. Older images cannot run Claude TTL sessions.
3. Use the updated Paddock CLI and inspect `paddock github status --json`. Its `poller` must be running with `runtime_version` at least 9 and compatible with the installed CLI. If an older poller is running, use `paddock github stop` followed by `paddock github start`; installing a new binary does not restart it. Verify the new poller status and `paddock runtime check`.
4. Set the deployed configuration's `idleTtl` to `"30m"` and restart Arnold with the rebuilt binary. Existing tasks and previously prepared dispatches retain their original TTL, including omission; deployment does not retrofit those tasks.

Validate the intended workspace and runtime before relying on a deployment:

1. Mention Arnold as a mapped user; verify the selected Paddock identity, OpenShell runtime and agent, public progress and answer.
2. With `requireMention: true`, reply without a mention and verify no work starts; mention Arnold again and verify only the new authored message is delivered to the existing native task. With the setting disabled, untagged replies continue active threads.
3. Restart the service; verify that routing, output delivery, streams and reaction cleanup continue without replaying completed work.
4. Check multiple mapped participants and an explicitly allowed automatic source. Unlisted bots must not dispatch work.
5. Exercise permitted engineering tools and PR creation with the configured identity. Merging and deployment require human review.
6. After an opted-in task expires, reply in its Slack thread and verify the task ID and saved conversation are reused, only the new follow-up is delivered, and the output cursor continues. Send all Claude TTL input through Arnold or `paddock message --external-id`; direct TUI input and native inbox writes fall outside the contract. Any delegated Paddock child needs its own `--idle-ttl 30m`.

A working provider does not eliminate native agent consent prompts. Claude may wait for project/MCP trust; Arnold does not simulate terminal approvals or silently broaden access. Workspace IDs, credentials, task identifiers and deployment-specific notes belong in ignored local files.
