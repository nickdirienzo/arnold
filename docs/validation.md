# Validation

Run the Go suite, race detector and static analysis:

```sh
go test -race ./...
go vet ./...
```

Tests use real SQLite, local HTTP/WebSocket servers and executable subprocess fixtures. They cover authenticated thread routing, source allowlists, identity and agent handoffs, new-message-only native continuations, durable retry prompts, uncertain delivery, Unicode/multipart output, cursor recovery, native assistant streams, 👀 reactions and graceful cancellation.

## State migration

`internal/arnold/testdata/node-state.sqlite` was generated by the original Node implementation using synthetic data only. The migration test copies it to a temporary directory and proves that the Go implementation preserves:

- Thread/identity bindings and the existing task reference.
- A frozen pending follow-up, including its original external ID and prompt.
- Output cursors and previously delivered output receipts.
- Stream timestamps and counters.
- Pending reaction metadata.

The same single-instance SQLite lease prevents the Go binary and Node service from owning a state database simultaneously. Database and sidecar files use owner-only access.

## Installed Paddock contract

```sh
ARNOLD_PADDOCK_TEST_BIN="$(command -v paddock)" go test -race ./...
```

This optional test runs the installed Paddock output CLI against a disposable registry and deterministic native RPC fixture. It exercises Paddock's actual opaque cursors, bounded pages, multipart answers and native turn completion, followed by delivery failure and service-state restart. It launches no model, uses no credentials and reads no existing tasks. Without the variable, the installed-CLI test is skipped.

## Binary and supervision

```sh
make build
bin/arnold version
mkdir -p state
bin/arnold launchd --directory "$PWD" > state/dev.arnold.slack.plist
plutil -lint state/dev.arnold.slack.plist
```

The binary is built with `CGO_ENABLED=0` and `-trimpath`. A live Node-to-Go handoff retained the existing routing, receipts, cursors, streams and reaction state, and the executable reconnected to Slack through launchd. SQLite is pure Go. The LaunchAgent invokes the executable directly and loads tokens from the local environment file.

## Live acceptance

Validate the intended workspace and runtime before relying on a deployment:

1. Mention Arnold as a mapped user; verify the selected Paddock identity, OpenShell runtime and agent, public progress and answer.
2. Reply without a mention; verify that only the new authored message is delivered to the existing native task.
3. Restart the service; verify that routing, output delivery, streams and reaction cleanup continue without replaying completed work.
4. Check multiple mapped participants and an explicitly allowed automatic source. Unlisted bots must not dispatch work.
5. Exercise permitted engineering tools and PR creation with the configured identity. Merging and deployment require human review.

A working provider does not eliminate native agent consent prompts. Claude may wait for project/MCP trust; Arnold does not simulate terminal approvals or silently broaden access. Workspace IDs, credentials, task identifiers and deployment-specific notes belong in ignored local files.
